# 授之以渔：先给框架

## 适用场景

下属说"不知道该怎么想"时；同一类问题反复出现时。

## 方法步骤

1. **显性化思维过程**：把自己处理这类问题的思考步骤讲出来，而不是只给结论。管理者本人就是教材——"我把自己放在第一用户的位置上，就是为了给你们当教材学习的"。
2. **提炼可复用框架**：把思维过程压成三步、三要素、四问这样可记忆的框架：
   - 报价三段式：多少价格 / 为什么这个价格 / 接下来干啥；
   - 预算三步法：整体够不够用 / 哪些可争取可砍 / 解决不了借多少；
   - 四问汇报框架：沟通了什么 / 达成什么共识 / 接下来做什么 / 可能遇到什么困难。
3. **用提问代替给答案**：下属来问时，先用框架反问："假设你是 CEO，你会怎么想？""如果选择一个最小行动，你会选择什么？"
4. **观察内化情况**：看下属能否脱离框架独立作答、能否用自己的话复述——内化的标志不是背出框架，而是能举一反三。

## 案例参照

- CEO 用"预算三步法"教 COO 做预算，用"报价三段式"教商务报价；
- 冲突之后，CEO 没有直接讲道理，而是要求新人用四问框架自己总结汇报。

## 常见误区

- 只给结论不给依据，下属学会"听指令"而不是"会思考"；
- 框架过多过杂，变成新的教条；框架是脚手架，最终要拆掉。

## 自检清单

- [ ] 我是否把"怎么想"讲清楚了，还是只说了"做什么"？
- [ ] 这个框架是否简短到可以被记住？
- [ ] 下属是否在用框架独立解决问题，而不是每次来问？
